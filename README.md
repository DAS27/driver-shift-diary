# Смена — дневник водителя

Мини-проект на **Go + HTML/CSS/JavaScript**: сводка заработка, поездки по дням и добавление поездок без дублей. Сервер и клиент собираются в один бинарный файл; сторонних Go- и JS-зависимостей нет.

![Интерфейс дневника](docs/screenshot.png)

## Быстрый запуск

Требуется **Go 1.25+**. Из корня репозитория:

```sh
make demo
```

Открыть **http://127.0.0.1:8080**. Команда копирует демоданные, только если рабочего файла ещё нет. По умолчанию интерфейс открывает последний день с поездками: **2 октября 2026**. На **1 октября** находятся ровно две поездки из задания.

Без `make`:

```sh
# Выполнить один раз перед первым запуском, если нужны демоданные:
cp data/trips.example.json data/trips.json
go run ./cmd/server
```

`go run ./cmd/server` без файла данных начинает с пустого дневника. Файл создаётся автоматически. Не копируйте пример поверх накопленных данных.

```sh
make test                 # тесты + race detector + покрытие
make check                # форматирование, go vet, тесты
make build
./bin/diary -addr 127.0.0.1:8081 -data ./data/my-trips.json -timezone Asia/Almaty
```

### Docker

```sh
docker compose up --build
```

Адрес тот же. Docker начинает с пустого дневника; добавьте поездку через интерфейс. Данные сохраняются в именованном томе `diary-data` между перезапусками. `docker compose down` сохраняет том, `down -v` удаляет его. Контейнер работает без root, с read-only корневой файловой системой; запись разрешена в том `/data`.

## Что сделано

- Сводка: количество поездок, выручка, комиссия, чистый доход, наличные/карта.
- Выбор произвольного дня, предыдущий/следующий день и кнопка «Сегодня».
- Список поездок с временем, длительностью, оплатой и доходом.
- Форма добавления, проверка данных в клиенте и на сервере.
- Пустые состояния, сообщения об ошибках, защита от устаревших ответов при быстром переключении дат, адаптивный интерфейс.
- JSON-хранилище, сохранение перед подтверждением запроса, атомарная замена файла, потокобезопасная дедупликация.
- Автотесты расчётов, API, конкурирующих запросов и перезапуска; GitHub Actions.

## Правила и допущения

- Валюта — **KZT**. JSON передаёт суммы в **тенге**, до двух знаков после точки. В Go деньги хранятся как `int64` в **тиынах**: нет накопления ошибок `float64`.
- Выручка = сумма `amount`; комиссия = сумма `commission`; **на руки = выручка − комиссия**. Это чистый доход со всех оплат, а не количество физических наличных.
- Для наличных и карты возвращаются отдельные количество, выручка, комиссия и чистый доход.
- День определяется по **началу** поездки в `Asia/Almaty` (на датах примера UTC+05:00). Поездка через полночь целиком относится ко дню начала. Часовой пояс настраивается; клиент использует его, а не часовой пояс компьютера.
- `start`/`end` — RFC3339 с `Z` или явным смещением; даты 2000–2100; `end > start`.
- `0 < amount ≤ 1 000 000 000`, `0 ≤ commission ≤ amount`; оплата только `cash` или `card`. Все пять полей обязательны. Экспоненциальная запись сумм, `null`, лишние поля и дроби точнее тиына отклоняются.
- Редактирование и удаление не входят в задание.

## API

### Список дней

```sh
curl http://127.0.0.1:8080/api/days
```

Ответ: `days` (даты по убыванию), `timezone`, `today` в часовом поясе сервера.

### Поездки и сводка

```sh
curl 'http://127.0.0.1:8080/api/day?date=2026-10-01'
```

```json
{
  "date": "2026-10-01",
  "timezone": "Asia/Almaty",
  "summary": {
    "count": 2,
    "revenue": 3900.00,
    "commission": 585.00,
    "net": 3315.00,
    "cash": {"count": 1, "revenue": 1500.00, "commission": 225.00, "net": 1275.00},
    "card": {"count": 1, "revenue": 2400.00, "commission": 360.00, "net": 2040.00}
  },
  "trips": [
    {"id":"t1","start":"2026-10-01T08:10:00+05:00","end":"2026-10-01T08:32:00+05:00","amount":2400.00,"payment":"card","commission":360.00},
    {"id":"t2","start":"2026-10-01T09:05:00+05:00","end":"2026-10-01T09:20:00+05:00","amount":1500.00,"payment":"cash","commission":225.00}
  ]
}
```

На пустой день: `200`, `trips: []`, нулевые суммы. Невалидная дата: `400`.

### Добавить поездку

```sh
curl -i http://127.0.0.1:8080/api/trips \
  -H 'Content-Type: application/json' \
  -d '{"id":"t8","start":"2026-10-03T08:10:00+05:00","end":"2026-10-03T08:32:00+05:00","amount":2400,"payment":"card","commission":360}'
```

- `201`: `{"created":true,"trip":{...}}`.
- Точный повтор: `200`, `created:false`, исходная поездка.
- Тот же `id`, другие данные: `409`, `error.code: "id_conflict"`.
- Некорректные поля: `400`; тип содержимого: `415`; тело более 16 KiB: `413`; ошибка записи: `500`.
- Ошибки API имеют вид `{"error":{"code":"invalid_trip","message":"..."}}`.
- `GET /healthz` — проверка работоспособности процесса.

### Как исключаются дубли

`id` необязателен при добавлении; без него сервер генерирует стабильный ID. Сравниваются **start + end + amount + payment + commission**. Время нормализуется к UTC, суммы — к тиынам. Одна поездка с новым ID или другим написанием смещения времени всё равно считается повтором; в ответе возвращается ID существующей записи.

Проверка и запись находятся под одним mutex. Параллельные повторы создают одну запись. При старте индексы восстанавливаются из файла, поэтому перезапуск не обнуляет защиту. Одинаковый ID с изменёнными данными всегда конфликтует. Повтор с другим ID не резервирует этот альтернативный ID.

В этом небольшом проекте две записи с полностью одинаковыми пятью полями считаются одной поездкой — это явное продуктовое допущение.

## Структура и ограничения

```text
cmd/server/          запуск, конфигурация, корректное завершение
internal/diary/      деньги, валидация, сводка, JSON-хранилище
internal/httpapi/    HTTP-контракт и интеграционные тесты
web/                клиент, встроенный через go:embed
data/               пример входных данных
```

Один водитель, один процесс и небольшой локальный JSON-файл. Запись выполняется через временный файл в том же каталоге, `Sync`, `Close`, `Rename`; память обновляется только после успешной замены. Повреждённый файл не перезаписывается: запуск завершается с ошибкой. Атомарная замена не является полной гарантией сохранности при аппаратном сбое/потере питания: каталог отдельно не синхронизируется.

Не запускайте два процесса на одном файле и не редактируйте его при работающем сервере: межпроцессной блокировки нет. Для нескольких экземпляров, больших объёмов или нескольких водителей следующий шаг — БД с транзакциями, уникальными ограничениями и авторизацией. Здесь авторизации нет; по умолчанию сервер доступен только на loopback. Для публикации сервиса потребуются HTTPS и контроль доступа. Публичный репозиторий содержит исключительно демонстрационные данные.

## Проверки

`go test -race ./...` проверяет:

- точные итоги примера, дробные суммы и пустой день;
- валидацию суммы, комиссии, оплаты, времени и ID;
- повтор с тем же/новым/отсутствующим ID, эквивалентные UTC-смещения;
- сохранение дедупликации после перезапуска и конфликт ID;
- 50 конкурентных повторов — ровно одно создание;
- смену календарного дня в Астане и поездку через полночь;
- ошибку записи без изменения памяти, последующую успешную попытку;
- испорченный JSON, HTTP-ответы, ограничения тела и выдачу клиента.
